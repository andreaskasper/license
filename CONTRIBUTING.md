# Contributing to FastFood License

Thank you for your interest in improving the FastFood License! 🍔

## How to Contribute

We welcome contributions in several areas:

### 1. 🌍 Translations

Help make the license accessible to more developers:

- Translate README.md to your language
- Translate license texts (FFM, FFS, FFE)
- Translate documentation (USAGE.md, FAQ.md, etc.)

**Requirements:**
- Maintain legal accuracy
- Keep the same structure
- Add your language to the main README

**File naming:**
- `README.{language-code}.md` (e.g., `README.fr.md`, `README.es.md`)
- `LICENSE-FFM.{language-code}.txt`

### 2. 📝 Documentation Improvements

- Fix typos or unclear wording
- Add examples
- Improve explanations
- Update outdated information

### 3. 📚 Real-World Examples

Share how you're using the FastFood License:

- Add to `examples/real-world/`
- Include: project name, variant used, link, brief description
- Screenshots welcome!

### 4. ⚖️ Legal Analysis

Help improve legal clarity:

- Point out ambiguities
- Suggest clearer wording
- Compare with established licenses
- Note jurisdiction-specific issues

**Note:** We appreciate legal expertise, but please note that contributors are not providing legal advice.

### 5. 🐛 Bug Reports

Found an issue?

- Typos in license text
- Broken links
- Incorrect comparisons
- Documentation errors

[Open an issue](https://github.com/andreaskasper/license/issues/new)

### 6. 💡 Feature Requests

Ideas for improvement:

- New documentation sections
- Tool integration
- Badge designs
- Package manager support

[Start a discussion](https://github.com/andreaskasper/license/discussions/new)

## Contribution Process

### Small Changes (typos, small fixes)

1. Fork the repository
2. Create a branch: `git checkout -b fix-typo`
3. Make your changes
4. Commit: `git commit -m "Fix typo in README"`
5. Push: `git push origin fix-typo`
6. Open a Pull Request

### Larger Changes (translations, new sections)

1. Open an issue first to discuss
2. Wait for feedback
3. Fork and create a branch
4. Make your changes
5. Reference the issue in your PR

## Style Guidelines

### Markdown

- Use ATX-style headers (`#` not `===`)
- Line length: ~80 characters for readability
- Use emoji sparingly and meaningfully
- Include examples where helpful

### License Text

**CRITICAL:** Changes to actual license text require careful review.

- Maintain legal clarity
- Keep structure consistent
- Don't change meaning without discussion
- Test with legal review if possible

### Tone

- Friendly and welcoming
- Clear and concise
- Professional but not stuffy
- Community-focused

## Commit Messages

**Good:**
- `Add French translation of README`
- `Fix typo in LICENSE-FFM.txt`
- `Add example: Vue.js project using FFM`
- `Improve FAQ section on commercial use`

**Bad:**
- `Update`
- `Fix`
- `Changes`

## What We Won't Accept

- Changes that fundamentally alter the gratitude focus
- Additions that make the license significantly more complex
- Proprietary or non-open licensing
- Content that violates our Code of Conduct

## Code of Conduct

### Our Pledge

We are committed to providing a welcoming and inspiring community for all.

### Our Standards

**Positive behaviors:**
- Using welcoming and inclusive language
- Being respectful of differing viewpoints
- Gracefully accepting constructive criticism
- Focusing on what is best for the community
- Showing empathy towards others

**Unacceptable behaviors:**
- Harassment of any kind
- Trolling or inflammatory comments
- Public or private harassment
- Publishing others' private information
- Conduct which could reasonably be considered inappropriate

### Enforcement

Instances of abusive, harassing, or otherwise unacceptable behavior may be reported by contacting the project team. All complaints will be reviewed and investigated promptly and fairly.
